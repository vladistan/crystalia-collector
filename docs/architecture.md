## 1. Architecture Overview

Crystalia Collector is a CLI tool that computes checksums for files stored in S3 and
produces RDF annotations describing those files using a LinkML-based data model. It
supports parallel processing of large files by splitting them into block-sized chunks
distributed across task files.

```
+-------------------+     +------------------+     +------------------+
|                   |     |                  |     |                  |
|    S3 Bucket      +---->+   CLI (Typer)    +---->+  Task Files      |
|                   |     |                  |     |  task_1..task_N   |
+-------------------+     +--------+---------+     +--------+---------+
                                   |                        |
                          +--------v---------+     +--------v---------+
                          |                  |     |                  |
                          |  Configuration   |     |  Checksum Engine |
                          |  (Pydantic)      |     |  (S3 byte-range) |
                          +------------------+     +--------+---------+
                                                            |
                          +------------------+     +--------v---------+
                          +------------------+     +--------v---------+
                          |                  |     |                  |
                          |  Monitoring      |     |  RDF Output      |
                          |  (Sentry/structlog)|   |  (LinkML/rdflib) |
                          +------------------+     +------------------+
```

The system runs in two modes:

- **Local**: Direct CLI invocation for small datasets
- **Distributed**: Nextflow orchestrates parallel execution on AWS Batch, each
  container processes a subset of task files

## 2. Components

### app.py — CLI Entry Point

Typer application with five commands:

| Command | Purpose |
|---------|---------|
| `list <prefix>` | List S3 files, optionally generate task files |
| `checksum <s3_url>` | Compute MD5 of a single S3 object or byte range |
| `annotate <task_file>` | Process task file lines, output RDF annotations |
| `combine` | Combine annotation files (placeholder) |
| `test-sentry` | Send test event to verify Sentry integration |

The `@app.callback()` initializes monitoring and logging on every command invocation.
Exit codes use an `ExitCode` IntEnum (OK=0, ERROR=1).

### config.py — Configuration Management

`CollectorSettings` extends Pydantic `BaseSettings` with a multi-source hierarchy:

1. Environment variables (`CRYSTALIA_` prefix)
2. `./crystalia.toml` (project-local)
3. `~/.config/crystalia-collector/config.toml` (user global)
4. Built-in defaults

Settings are loaded once via `get_settings()` (LRU cached). A `model_validator`
resolves the Sentry DSN through a fallback chain: `CRYSTALIA_SENTRY_DSN` env var ->
bare `SENTRY_DSN` env var -> project default DSN (when telemetry enabled).

### work.py — Core Workflow

Two main functions:

**`list_s3_dir(prefix, method_id, task_dir)`**
- Iterates over all objects under an S3 prefix
- Classifies files as "small" (< 16 MB or < half the block size) or "large"
- Small files are batched into a single task file
- Large files are split by block offset, one task file per block
- Returns (num_files, total_size)

**`compute_annotations(output_file, task_file)`**
- Reads a task file line by line
- Each line: `s3://bucket/key size method block_size offset`
- Calls `compute_s3_checksum()` for each line
- Writes `<s3://url> hexdigest` to output

### s3_iface.py — S3 Interface

**`S3Object`** dataclass: key, last_modified, etag, size.

**`list_files_in_s3_prefix(bucket, prefix)`** — Paginated S3 listing using
continuation tokens. Yields `S3Object` instances.

**`compute_s3_checksum(bucket, key, offset, length)`** — Downloads the specified
byte range from S3 and computes MD5 in 8 KB chunks. Returns hex digest string.

### rdf.py — RDF Generation

Bridges between Python dataclasses (generated by LinkML) and RDF graphs (rdflib).

**`get_schema()`** — LRU-cached `SchemaView` loaded from `crystalia.yaml`.

**`rdf_from_model(thing)`** — Converts a LinkML `Thing` instance to an RDF `Graph`
using `RDFLibDumper`.

**`model_from_rdf(rdf, type_class, subject)`** — Loads an RDF graph back into a
Python dataclass using `RDFLibLoader`. Optional `subject` parameter filters triples
to a specific URI.

### monitoring.py — Observability

**`init_monitoring(dsn)`** — Initializes Sentry SDK with configurable trace sampling
(default 3%), environment tag, and release version. No-op when DSN is None/empty.

**`configure_logging(json_output)`** — Sets up structlog with context variable
merging, ISO timestamps, and a renderer (JSON or console depending on setting).

### util.py — Utilities

**`human_readable_size(bytes)`** — Formats byte counts to PB/TB/GB/MB/KB.

**`stream_offsets(blocksize, length)`** — Generator yielding offsets from 0 to
length in blocksize steps.

**`process_file(bucket, file, method, task_dir, task_num, small_files)`** —
Routing logic: appends small files to batch list, writes task files for large files
(one per block offset for bounded methods, one total for unbounded).

**`write_task_file(task_dir, task_num, method, bucket, content, offset)`** —
Writes a task file with format: `s3://bucket/key size method_id block_size offset`
per line.

### method/ — Checksum Methods

**`GenericMethod`** base class with two attributes:
- `block_size` (int) — 0 means unbounded (process entire file)
- `id` (str) — method identifier

Property `needs_offsets` returns True when `block_size != 0`.

Three MD5 implementations:

| Class | ID | Block Size |
|-------|----|------------|
| `MD5_Unbounded` | `md5` | 0 (entire file) |
| `MD5_2GB` | `md5-2gb` | 2 GB |
| `MD5_8GB` | `md5-8gb` | 8 GB |

**`method_by_id(method_id)`** — Factory function returning the appropriate
method instance.

## 3. Data Model

The data model is defined in LinkML and vendored from the `crystalia-data-model`
project. Source schema: `src/crystalia_collector/data/linkml/crystalia.yaml`.
Generated Python dataclasses: `src/crystalia_collector/data/linkml/crystalia.py`.

### Class Hierarchy

```
Thing (id)
  |
  +-- DescribableThing (hasDescriptor[])
  |     |
  |     +-- Item (label, isPartOf)
  |     |
  |     +-- Descriptor (label, hasType, value, offset, length, coverage)
  |
  +-- DescriptorType (label, usesMethod, max_block_size)
  |
  +-- Method (label, comment, robustness)
```

### Classes

**Thing** — Base class. Has a required `id` (URI or CURIE).

**DescribableThing** — Extends Thing. Has zero or more `Descriptor` references.

**Item** — A file or data object. Has a `label` (typically filename) and
`isPartOf` (dataset URI).

**Descriptor** — An annotation on an Item or another Descriptor. Carries a `value`
(the computed hash), `offset` and `length` (byte range), `coverage` (0.0-1.0),
and references a `DescriptorType`.

**DescriptorType** — Metadata about a descriptor category. References a `Method`
and optionally specifies `max_block_size`.

**Method** — A computation method (e.g., MD5). Has a `robustness` enum value.

### Robustness Enum

```
EXTREMELY_HIGH  — e.g., SHA512
VERY_HIGH       — e.g., MD5
HIGH            — e.g., Farmhash, Jenkins
MODERATE        — e.g., CRC
LOW             — e.g., length + date + name together
VERY_LOW        — e.g., length, date, or name individually
```

### Prefixes

| Prefix | Namespace |
|--------|-----------|
| `crys` | `https://w3id.org/crystalia/` |
| `cryd` | `https://crystalia.link/data/` |
| `dct` | `http://purl.org/dc/terms/` |
| `qudt` | `http://qudt.org/schema/qudt/` |

## 4. Data Flow

### List and Task Generation

```
S3 Bucket (prefix)
       |
       v
list_files_in_s3_prefix()       Paginated listing via continuation tokens
       |
       v
  For each S3Object:
       |
       +-- Small file? (<16MB or <half block_size)
       |       |
       |       v
       |   Collect into small_files[]
       |       |
       |       v
       |   Single task file with all small files
       |
       +-- Large file, unbounded method?
       |       |
       |       v
       |   One task file: full file, offset=0
       |
       +-- Large file, bounded method?
               |
               v
           stream_offsets(block_size, file.size)
               |
               v
           One task file per block offset
```

### Task File Format

Each line in a task file:

```
s3://bucket/key size method_id block_size offset
```

Example:

```
s3://my-bucket/data/file1.vcf.gz 17179869184 md5-8gb 8589934592 0
s3://my-bucket/data/file1.vcf.gz 17179869184 md5-8gb 8589934592 8589934592
```

### Annotation Pipeline

```
Task File (task_N)
       |
       v
compute_annotations()
       |
       +-- For each line:
       |       |
       |       v
       |   Parse: bucket, key, size, method, block_size, offset
       |       |
       |       v
       |   compute_s3_checksum(bucket, key, offset, block_size)
       |       |
       |       v
       |   S3 GetObject (Range: bytes=offset-offset+length-1)
       |       |
       |       v
       |   MD5 hash in 8KB chunks
       |       |
       |       v
       |   Write: <s3://url> hexdigest
       |
       v
Output File (out.rdf)
```

## 5. Configuration Reference

### Settings Class: `CollectorSettings`

| Setting | Type | Default | Env Var |
|---------|------|---------|---------|
| `default_method_id` | str | `md5-8gb` | `CRYSTALIA_DEFAULT_METHOD_ID` |
| `default_output_file` | str | `out.rdf` | `CRYSTALIA_DEFAULT_OUTPUT_FILE` |
| `enable_telemetry` | bool | `false` | `CRYSTALIA_ENABLE_TELEMETRY` |
| `sentry_dsn` | str\|None | None | `CRYSTALIA_SENTRY_DSN` |
| `sentry_environment` | str | `development` | `CRYSTALIA_SENTRY_ENVIRONMENT` |
| `log_json` | bool | `true` | `CRYSTALIA_LOG_JSON` |

### Source Priority

1. **Environment variables** — `CRYSTALIA_` prefix (highest)
2. **Project-local TOML** — `./crystalia.toml`
3. **User global TOML** — `~/.config/crystalia-collector/config.toml`
4. **Built-in defaults** (lowest)

### Sentry DSN Resolution

The DSN resolves through a chain:

1. `CRYSTALIA_SENTRY_DSN` env var
2. Bare `SENTRY_DSN` env var (fallback for CI/Heroku)
3. Project default DSN (only when `enable_telemetry=true`)
4. None (Sentry disabled)

### Monitoring Settings

| Env Var | Default | Description |
|---------|---------|-------------|
| `SENTRY_TRACES_SAMPLE_RATE` | `0.03` | Fraction of transactions sampled |
| `SENTRY_ENVIRONMENT` | `development` | Environment tag |

## 6. Nextflow Pipelines

### gen_annotations.nf

Three-process pipeline using DSL2:

```
listFiles --> generateRDF --> uploadToBucket
```

**Parameters:**

| Parameter | Description |
|-----------|-------------|
| `params.s3Uri` | S3 prefix to process |
| `params.s3OutUri` | S3 destination for combined output |

**Processes:**

**listFiles** — Runs `crystalia-collector list` with `--task-dir` to generate task
files. Outputs `task_*` files.

**generateRDF** — Takes one task file as input, runs `crystalia-collector annotate`.
Outputs `out.rdf`. Processes run in parallel (one per task file) via the `flatten`
operator.

**uploadToBucket** — Collects all RDF outputs via `collectFile()` and uploads to S3
using `aws s3 cp`.

### Pipeline Flow

```
params.s3Uri
       |
       v
  listFiles
       |
       v
  task_1, task_2, ..., task_N     (flatten)
       |         |            |
       v         v            v
  generateRDF  generateRDF  generateRDF   (parallel)
       |         |            |
       v         v            v
  out.rdf    out.rdf      out.rdf         (collectFile)
       |
       v
  uploadToBucket --> params.s3OutUri
```

### nextflow.config

| Setting | Value |
|---------|-------|
| Executor | AWS Batch |
| Platform | FARGATE |
| Job Queue | `crystalia-collector-batch-process-2` |
| Container | ECR image (tagged `v0.14`) |
| Region | `us-east-1` |
| Job Role | `crystalia-collector-batch-task-ecs` |

## 7. Infrastructure

Pulumi stack in `infrastructure/` manages the AWS resources required for distributed
execution. Stack name: `crystalia-collector-batch-infra`.

### Resources

| Resource | Type | Name |
|----------|------|------|
| ECR Repository | `aws.ecr.Repository` | `crystalia-collector-batch-repo` |
| Compute Environment | `aws.batch.ComputeEnvironment` | EC2-based, max 240 vCPUs |
| Job Queue | `aws.batch.JobQueue` | `crystalia-collector-batch-process-2` |
| Job Definition | `aws.batch.JobDefinition` | FARGATE, 1 vCPU, 2048 MB |
| S3 Work Bucket | `aws.s3.BucketV2` | `crystalia-collector-batch-work-bucket` |
| Task Role | `aws.iam.Role` | ECS task role with S3 + ECR + CloudWatch permissions |
| Instance Profile | `aws.iam.InstanceProfile` | For EC2 compute environment |

### Network

The compute environment uses VPC resources imported from a Terraform remote state
(`db-tform-state` S3 bucket, key `tubes/v1`):

- Private subnet
- Security groups for admin access and outbound traffic

### IAM Permissions

The task role grants:

- `s3:GetObject`, `s3:PutObject`, `s3:DeleteObject`, `s3:ListBucket` on all S3
  buckets (including 1000genomes data)
- ECR image pull permissions
- CloudWatch Logs write permissions

### Exports

| Export | Description |
|--------|-------------|
| `ecr_repo_url` | ECR repository URL for Docker pushes |
| `bucket_name` | Work bucket name |

## 8. Extensibility

### Adding a New Checksum Method

1. Create a new class in `src/crystalia_collector/method/`:

```python
from crystalia_collector.method.generic import GenericMethod

class SHA256_4GB(GenericMethod):
    def __init__(self) -> None:
        super().__init__()
        self.id = "sha256-4gb"
        self.block_size = 4 * 2**30
```

2. Register it in the `method_by_id()` factory in `method/md5.py` (or move the
   factory to `__init__.py` as methods grow):

```python
elif method_id == "sha256-4gb":
    return SHA256_4GB()
```

3. Update `compute_s3_checksum()` in `s3_iface.py` if the new method uses a
   different hash algorithm (currently hardcoded to `hashlib.md5()`).

4. Add the method's robustness level to the LinkML schema enum if needed.

### Adding a New Data Source

The S3 interface is in `s3_iface.py`. To support a different storage backend
(e.g., GCS, Azure Blob, local filesystem):

1. Create a new interface module (e.g., `gcs_iface.py`) implementing:
   - A listing function that yields objects with key, size, last_modified, etag
   - A checksum function that reads byte ranges and returns hex digests

2. Update `work.py` to select the appropriate interface based on the URI scheme
   (`s3://`, `gs://`, `file://`).

3. The `S3Object` dataclass can be generalized to a `StorageObject` or kept as-is
   with a new parallel dataclass.

### Adding a New Output Format

RDF output is handled in `rdf.py`. To add alternative formats:

1. Create a new output module (e.g., `json_output.py`) that takes `Thing` instances
   and serializes them.

2. Update `compute_annotations()` in `work.py` to select the output writer based
   on configuration or file extension.

3. The LinkML runtime supports multiple serialization formats (JSON-LD, YAML, CSV)
   via its dumper classes — these can be used directly:

```python
from linkml_runtime.dumpers import JSONDumper, YAMLDumper
JSONDumper().dump(thing, to_file="output.json")
```
